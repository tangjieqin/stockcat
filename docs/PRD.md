# StockCat 产品需求文档（PRD）

- 文档版本：V1.0-Draft
- 状态：待评审
- 产品形态：个人使用、本地部署的行情监控与复盘工具；第一版仅在本机运行，只服务项目所有者本人的日常监控
- 目标用户：单一用户（项目所有者）

## 1. 产品概述

StockCat 用于集中查看自选股票与基金的行情、设置价格/涨跌幅等告警规则、记录告警事件并发送通知；同时提供**手工交易流水记录与持仓盈亏计算**、**市场复盘与个人投资日记**，帮助把行情、操作和思考沉淀在同一处。后续逐步扩展技术指标、ETF/LOF 溢价监控、AI 每日复盘和资料检索。

产品定位是"行情监控、持仓记录、信息汇总与复盘辅助"，不是自动交易系统，也不输出确定性的买入/卖出指令。持仓数据来自用户手工录入的交易流水，不对接券商、不自动同步。

## 2. 产品目标

### 2.1 P0 目标
1. 用户可以维护自选标的。
2. Java 服务可以从经过验证的数据源获取 A 股及选定 ETF/LOF 的实时快照。
3. 前端可以查看最近一次行情及更新时间，并能区分正常、延迟、缺失等状态。
4. 用户可以创建、启用、停用和删除基础告警规则。
5. 服务按配置的周期检查规则，生成可追踪的告警事件，避免同一条件短时间内重复触发。
6. 告警事件和通知发送结果持久化；至少打通邮件与一种经验证的推送渠道。
7. 用户可手工记录交易流水（买入/卖出），系统据此确定性计算当前持仓、成本与盈亏。
8. 用户可按交易日创建市场复盘（市场主要情况、板块表现），并维护一个树状目录的长期个人笔记本（我的日记），可关联标的与告警事件。
9. 首页总览聚合市场概况（指数行情）、重点行情、持仓表现和待处理告警。
10. 提供健康检查、日志和最小化的测试，支持本地运行和排障。

### 2.2 非目标
P0 不包含自动下单、券商账户接入、投资组合自动调仓、多人多租户、复杂权限、移动端原生应用、全市场高频行情、保证交易所级实时性、保证盈利的投资建议。持仓与交易流水为**手工录入**，不做券商同步、文件导入（P4 再评估）、自动撮合或税务计算。

本地部署定位下，第一版暂不考虑：注册登录、多人协作、云端同步、移动端/手机端适配、公网访问与 HTTPS 部署。这些能力留待确有需要时（P4）重新评估。

## 3. 用户场景

- 作为用户，我希望把关注的股票/ETF 加入自选列表，方便集中查看。
- 作为用户，我希望查看最新价格、涨跌幅、行情时间和数据状态。
- 作为用户，我希望设置价格高于/低于阈值或涨跌幅达到阈值时收到提醒。
- 作为用户，我希望查看告警触发时间、触发时行情、规则名称和通知状态。
- 作为用户，我希望知道行情或通知服务异常，而不是看到看似正常的旧数据。
- 作为用户，我希望手工记录买入/卖出操作，随时查看当前持仓、成本和盈亏。
- 作为用户，我希望按日期写市场复盘和个人投资日记，并能把日记关联到具体标的和告警事件。
- 作为用户，我希望打开首页就能看到市场概况、我的持仓表现和待处理的告警。
- 后续：我希望查看技术指标、基金溢价相关数据，并让 AI 基于系统数据生成每日复盘草稿（经我确认后保存）。

## 4. 版本范围

### P0：行情、告警、持仓与记录闭环
- 首页总览：指数市场概况、重点行情摘要、持仓表现摘要、待处理告警、复盘入口。
- 监控标的管理：确定告警引擎监控哪些标的。
- 自选标的管理：添加、查看、删除；标的代码和市场类型必须明确。
- 行情快照：定时采集（自选/监控标的 + 首页指数）、标准化、保存必要的最新快照。
- A 股交易日历与交易时段判断。
- 基础告警：最新价高于/低于阈值、涨跌幅高于/低于阈值。
- 告警事件列表及详情、通知记录、发送结果和失败原因。
- 交易流水：手工录入买入/卖出（价格、数量、费用、时间），可编辑删除。
- 持仓与盈亏：由有效交易流水确定性计算（数量、摊薄成本、市值、浮动/已实现盈亏）。
- 复盘：市场复盘按交易日记录（一天一篇，含市场主要情况与板块表现）；我的日记为仿飞书文档的树状长期笔记本（文件夹/文档，深度 ≤5），支持创建、编辑、移动、检索，可关联标的与告警事件。
- 系统状态页或状态区域：Java、数据库、行情采集器、通知配置状态。
- Python FastAPI 骨架与健康检查；暂不要求完整 Agent 和完整历史数据适配器。

### P1：历史数据与技术指标、基金数据
- Python 历史行情适配器，先验证日 K 或可稳定获取的分钟 K 数据。
- Java 使用 ta4j 计算 MACD、RSI、KDJ 等约定指标，避免 Java/Python 双重实现。
- ETF/LOF 的 IOPV、净值、价格和溢价率监控；先核实每类产品可获得的数据定义和更新频率。
- 数据质量检查、缺失数据处理和指标结果展示。
- 收益曲线、持仓变化分析与历史持仓快照。

### P2：AI 每日复盘
- Python + LangChain Agent。
- Agent 通过 Java 受控只读 API 查询行情、自选、持仓、告警和日记所需数据。
- 生成每日市场复盘**草稿**，由用户确认、修改后才保存，AI 不直接落库。
- 对个人投资日记进行结构化整理和历史回顾辅助。
- AI 输出摘要、数据引用/时间戳和不确定性说明。
- Agent 不直接写业务数据库，不直接更改告警规则或发送业务通知。

### P3：资料检索
- 新闻、公告、研究资料的导入与检索。
- PostgreSQL pgvector 作为后续可选能力，不属于 P0 必需依赖。
- 将历史日记、复盘和市场事件关联起来，为复盘提供可追溯的信息来源。

### P4：扩展
- 港股、美股、更多基金和数据源。
- 交易文件导入、数据备份恢复工具化。
- 云端部署、多设备同步、备份恢复和多用户能力（确有需要时再设计）。

## 5. 核心业务规则

1. 所有行情必须携带数据源、行情时间、采集时间和状态；展示时不能把旧快照伪装成实时数据。
2. 行情轮询间隔初始建议 5 分钟，可配置。该频率表示“采集快照频率”，不代表生成了真实的 5 分钟 K 线。
3. 交易日和交易时段以 `trading_calendar` 为依据；节假日、临时休市和数据源异常均需考虑。
4. 非交易时段可以不采集，或按配置进行低频采集；行为必须在配置中明确。
5. 告警只在行情数据有效且足够新时判断；过期或缺失数据不触发正常价格告警，并应记录数据状态。
6. 告警事件和通知记录分开保存。事件触发不等于通知成功。
7. 同一规则的重复触发应有冷却时间或状态边沿判断，避免持续满足条件时不断推送。
8. 所有价格、百分比、数量等字段使用明确的数据类型和单位；百分比统一约定为“百分数值”还是“小数比例”，不得混用。本项目 API 统一使用百分数值，例如 2.5 表示 2.5%。
9. 不把数据供应商未经验证的接口当作永久稳定、免费或具有 SLA 的服务。
10. AI 结果只用于信息整理和解释，必须显示生成时间及其使用的数据时间范围。
11. 持仓由有效交易流水**确定性计算**：买入按加权平均更新摊薄成本；卖出减少数量并按当时成本结转已实现盈亏；不允许卖出超过当前持有数量。市值与浮动盈亏基于最新有效快照计算，行情缺失时相应字段留空而非按 0 计算。
12. 交易流水是持仓的唯一事实来源；修改或删除流水必须重新计算受影响持仓，计算逻辑有单元测试。
13. 市场复盘（按交易日）与我的日记（树状笔记本）是两个独立模块，均由用户手工创建和修改；市场复盘一天一篇；AI 只能生成复盘草稿供确认（P2），不得自动保存或覆盖用户内容。

## 6. 页面范围（一级导航）

- **首页 · 总览**：市场概况（指数）、重点行情、持仓表现、待处理告警、复盘入口。
- **告警**：告警总览 / 监控标的 / 告警规则 / 告警历史。规则定义条件，监控标的确定监控对象，历史记录每次触发结果与通知状态。
- **我的股票**：自选列表 / 我的持仓 / 交易流水 / 持仓变化（P1）。自选负责关注，交易流水负责记录操作，持仓根据有效交易计算。
- **复盘**：市场复盘（按交易日）/ 我的日记（树状长期笔记本）。复盘记录市场，日记沉淀个人思考，分开存储，可关联标的和告警事件。
- **其他**：数据源状态 / 通知配置 / 系统状态 / 数据备份（P4 工具化）/ AI 配置（P2）。

- P1：指标详情、基金溢价详情、持仓变化分析。
- P2：AI 复盘草稿确认页与 AI 配置。

## 7. 非功能要求

- 可维护性：模块边界清楚，外部数据源通过适配器隔离。
- 可观测性：关键任务有日志、耗时、结果和错误原因。
- 数据质量：保留行情时间和采集时间，能够识别过期数据。
- 安全性：密钥只通过环境变量或本地未提交配置提供；不得提交真实凭据。
- 可恢复性：数据库迁移可重复执行或明确版本；本地数据应可备份。
- 测试性：规则判断、冷却逻辑、交易时段判断、数据标准化和**持仓计算**应有单元测试。
- 运行要求：P0 面向普通开发电脑，不依赖独立显卡；AI 功能在 P2 才引入外部模型/API。

## 8. P0 验收标准

1. 可按 README 在目标开发环境启动前端、Java 服务、PostgreSQL 和 Python 骨架。
2. 用户可添加一个标的，并在页面看到标的代码、最新价、涨跌幅、行情时间和数据状态。
3. 数据源不可用时，系统显示异常或过期状态，不生成虚假的最新行情。
4. 用户可创建、停用和删除价格/涨跌幅规则。
5. 可通过测试行情或可控测试夹具验证：规则满足时生成一条告警事件。
6. 重复轮询时，冷却机制可以阻止同一规则短时间内重复通知。
7. 告警事件和通知记录均可查询；通知失败可追踪失败原因。
8. 核心 API 有请求/响应示例和自动化测试。
9. P0 不依赖 Redis、Kafka、pgvector 或 AI 模型服务。
10. 录入一买入一卖出流水后，持仓数量、摊薄成本、已实现盈亏与手工计算一致；卖出数量超过持有量时被拒绝并提示。
11. 可创建、编辑、查询市场复盘（同日重复创建被拒绝）；我的日记可新建文件夹和文档、移动位置、按关键词检索；删除有确认。
12. 首页总览展示指数行情、持仓摘要和待处理告警，各摘要可点击进入对应页面。

## 9. 数据源与外部依赖风险

- Eastmoney Push2 作为实时快照候选源，必须先验证可访问性、字段含义、频率限制、稳定性及使用条件。
- 邮件和 Server酱/PushPlus 选择其中一种推送渠道作为首个实现对象；实际接入前验证账号、接口、配额和可用性。
- Python 历史行情、IOPV、净值等适配器须逐类验证来源和字段定义。
- 对无法确认的接口或字段，在设计文档中标记“待验证”，不要伪造成功结果。

## 10. 术语

- 行情时间：数据源声称该行情对应的时间。
- 采集时间：本系统收到/保存数据的时间。
- 行情快照：某一时刻的价格等行情字段，不等于完整 K 线。
- 告警规则：用户配置的判断条件。
- 告警事件：某次规则满足时创建的持久化记录。
- 通知记录：向具体渠道发送告警消息的结果。
- 交易流水：用户手工记录的一次买入或卖出操作，是持仓计算的唯一事实来源。
- 摊薄成本：多次买入后按加权平均计算的单位成本，卖出时结转。
- 监控标的：被告警引擎采集和评估行情的标的集合，与自选列表相互独立。
- 市场复盘：针对某个交易日市场的整体记录与思考。
- 我的日记：个人长期笔记本，树状目录组织（文件夹/文档），与按日期的市场复盘分开存储。
- 市场复盘：针对某个交易日市场的整体记录与思考，含市场主要情况与板块表现，一天一篇。
