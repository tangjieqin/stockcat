# StockCat 页面与交互设计（UI）

- 文档版本：V1.1-Draft
- 目标：定义页面结构、交互与状态；具体视觉细节可在原型阶段调整。
- 配套原型：`docs/prototype.html`（静态 HTML，内含 P0 页面的线框实现、状态样式与弹窗交互；页面数据均为模拟数据，仅用于评审）。
- P0 原则：先可用、清晰、轻量，不追求复杂大屏或 3D 效果。
- 桌面端优先：第一版本地部署、仅在桌面浏览器使用，暂不考虑手机端适配。

## 1. 导航结构

左侧边栏，一级菜单五个分组：

1. **首页 · 总览**——市场概况、重点行情、持仓表现、待处理告警、复盘入口。
2. **告警**（子菜单）
   - 告警总览：规则状态 + 最近事件 + 通知状态一览。
   - 监控标的：确定告警引擎监控哪些标的。
   - 告警规则：定义触发条件。
   - 告警历史：每次触发的结果与通知状态。
3. **我的股票**（子菜单）
   - 自选列表：关注但不一定持有。
   - 我的持仓：由有效交易计算的结果。
   - 交易流水：手工记录每次买卖操作。
   - 持仓变化（P1）：历史持仓快照与收益曲线。
4. **复盘**（子菜单）
   - 市场复盘：按交易日记录市场主要情况与不同板块表现；一天一篇。
   - 我的日记：个人长期笔记本，仿飞书文档的树状目录（文件夹/文档），不按日期组织。
5. **其他**
   - 数据源 / 通知配置 / 系统状态（P0）。
   - 数据备份（P4 工具化）/ AI 配置（P2，占位禁用）。

关系约定：**监控标的**决定采集与告警评估范围，与**自选列表**相互独立；一个标的可以只在其中一边。

## 2. 页面说明

### 2.1 首页 · 总览

目标：打开即回答"市场怎么样、我的持仓怎么样、有没有要我处理的告警"。

页面区域：
- 市场概况卡：上证指数 / 深证成指 / 创业板指的点位、涨跌幅、行情时间与数据状态（内置配置，不属于监控标的）。
- 持仓表现卡：总市值、总浮动盈亏、持仓只数；无持仓时引导去记录交易。
- 待处理告警卡：今日触发的告警事件（时间、标的、规则），点击进入告警历史。
- 重点行情卡：自选/监控标的中涨跌幅居前的若干条。
- 复盘入口卡：最新一篇市场复盘的日期与标题，无则显示"写今日复盘"。

交互：任一卡片可点击跳转对应页面；某数据块失败时该卡显示错误态，不影响其他卡。

### 2.2 告警总览

- 规则统计：启用中 / 已停用数量。
- 今日事件列表（最近 10 条）：时间、标的、规则、通知状态。
- 通知渠道健康：邮件 / 推送渠道最近发送结果。

### 2.3 监控（原「监控标的」）

表格列：代码、名称、类型、持仓（由交易流水实时推导：当前净持仓 > 0 显示「持仓中」）、最新价、涨跌幅、行情时间、数据状态、监控状态（启用/停用）、操作。
交互：
- [添加监控] 弹窗：市场（P0 仅 A 股）、代码、类型；名称由服务端主数据补全。**可勾选「同时创建告警规则」**（默认开启）：选择类型/阈值/冷却，规则名按 `{标的名称} {条件}{阈值}` 自动拼接，创建失败不影响已添加的监控。
- 停用后不参与采集与告警评估，保留配置。
- 移除需确认（其告警规则保留，可在规则页清理）。

### 2.4 告警规则

规则列表字段：规则名称、标的、规则类型、参数摘要、启用状态、冷却时间、最近触发时间、操作。
P0 类型：`PRICE_ABOVE` / `PRICE_BELOW` / `CHANGE_PERCENT_ABOVE` / `CHANGE_PERCENT_BELOW`。
参数约定：`params` 结构由规则类型决定——价格类填价格；涨跌幅类用百分数值，跌幅用负数（如"跌 20%"填 `-20`）。条件判断含边界（≥ / ≤）。
创建/编辑表单（参数表单随规则类型切换）：
- 规则名称（**自动拼接**：`{标的名称} {条件}{阈值}`，如「贵州茅台 价格≥1000」；编辑时可改名）
- 标的（单选，取自监控标的；或切换为"多选"批量创建同类型同参数规则）
- 规则类型 → 对应的参数输入（P0 为阈值一个字段；P1 溢价率/指标类型出现各自参数）
- 冷却时间（非负整数，默认 30 分钟）
- 是否启用
- 服务端校验：类型所需数据未接入时（如溢价率），类型选项置灰并提示"该类型需要 IOPV 数据（P1）"。
交互：保存成功后更新列表；停用规则不再产生新事件但保留历史；删除需二次确认，历史事件保留规则类型与参数快照。
多规则：同一标的可同时挂多条不同类型/不同参数的规则（如 a 股票同时监控溢价率、价格、跌幅），各规则独立评估、独立冷却、独立产生事件；规则列表支持按标的筛选，查看某只股票的全部规则。

### 2.5 告警历史

列表字段：触发时间、标的、规则名称、条件快照、触发值、当时涨跌、行情时间、通知状态、操作[详情]。
筛选：时间范围、标的、规则、通知状态；分页，默认触发时间倒序。
详情弹窗：规则快照、触发时行情、通知记录列表；失败通知可重试（仅 FAILED 可重试）。

### 2.6 自选列表

表格列：代码、名称、市场/类型、最新价、涨跌幅、行情时间、采集时间、数据状态、操作。
交互：[添加自选] 弹窗；移除确认；点击标的可查看详情。
说明：自选与监控标的独立管理，互不影响。

### 2.7 我的持仓

表格列：代码、名称、持有数量、摊薄成本、最新价、市值、浮动盈亏、已实现盈亏、行情时间、数据状态。
- 市值/浮动盈亏基于最新有效快照；快照缺失或过期时显示"—"，不按 0 计算。
- 空状态：尚无持仓，引导去记录交易流水。
- 说明区：注明"持仓由交易流水计算，非券商同步数据"。

### 2.8 交易流水

表格列：成交时间、标的、方向（买入/卖出）、成交价、数量、费用、金额、备注、操作[删除]。
筛选：标的、方向、时间范围。
交互：
- [记录交易] 弹窗：标的、方向、成交价、数量、费用、成交时间、备注。
- 卖出数量超过持有量时，后端拒绝（409）并在表单显示"当前可卖 N 股"。
- 删除流水需确认；删除后持仓自动重算。

### 2.9 市场复盘

一天一篇（已存在时显示"查看/编辑今日复盘"）。
列表列：日期、标题、更新时间、操作。
编辑器分区：**市场主要情况** / **板块表现** / 完整正文（Markdown）/ 关联告警事件多选。
检索：日期范围、关键词。
交互：保存成功反馈；删除二次确认；AI 草稿（P2）带"AI 草稿"标识，用户确认后才转为正式复盘。

### 2.10 我的日记（树状笔记本）

布局：左树右文（左侧目录树 + 右侧文档编辑区），仿飞书文档。
- 树节点：文件夹 📁 / 文档 📄，支持展开收起、同级拖拽或按钮排序。
- 树操作：新建文件夹 / 新建文档 / 重命名 / 移动（改父级，服务端校验成环与深度 ≤5）/ 删除。
- 删除文件夹：强确认弹窗必须显示"将删除 N 个文件夹和 M 篇文档"。
- 右侧编辑区：标题、正文（Markdown）、关联标的多选。
- 检索：关键词搜索命中文档列表，点击定位到树中位置。
- 空状态：引导"新建第一个文件夹"。

### 2.11 其他页（P0）

- 数据源：各数据源状态、最近成功/失败、频率配置展示。
- 通知配置：邮件 SMTP 配置说明（密钥走环境变量）、推送渠道 token 状态（不显示明文）、测试发送按钮。
- 系统状态：Java、PostgreSQL、行情采集器、通知渠道、Python 服务的健康卡片与最近错误摘要。
- 不向浏览器暴露堆栈、密钥或内部路径。

## 3. 全局交互状态

每个数据页面都要定义：
- 初次加载：骨架屏或加载提示。
- 空状态：解释为什么为空，并提供下一步操作。
- 请求失败：错误提示 + 重试入口。
- 部分数据缺失：明确标记，不用 0 代替未知值。
- 数据过期：展示最后更新时间。
- 保存中：禁用重复提交并显示进度。
- 操作成功：明确反馈。
- 删除/不可逆操作：确认后执行。
- 服务未启动：提示检查服务状态，不暴露内部异常详情。

## 4. 视觉风格建议

- 简洁的金融工具风格，信息密度适中。
- 使用中性色为主；涨跌色遵循 A 股惯例**红涨绿跌**，全站一致。
- 状态不能只依赖颜色，同时配文字或图标。
- 数字采用等宽数字或对齐格式；价格小数位按品种精度（A股 2 位），涨跌幅固定一位小数，百分比统一"百分数值"。
- 不使用夸张的"买入/卖出"按钮，不把指标展示包装成确定性投资结论。
- 桌面端优先（设计基准宽度 ≥1280px），暂不考虑手机端适配。

## 6. 前端实现约定

- Vue 3 + TypeScript + Vite + Pinia。
- 页面组件只负责展示和交互；请求统一通过 API client 层发出。
- API 类型与 `API.md` 保持一致（含 `/dashboard`、`/trades`、`/positions`、`/recaps`、`/diary`、`/monitor-targets`）。
- 统一处理 HTTP 错误、加载状态和用户提示。
- P0 使用普通表格和轻量图表（如确有需要），不做复杂动画或 3D 场景。

## 7. 原型验收

- 所有 P0 页面均有默认、加载、空、错误状态。
- 表格列名、单位和状态含义明确。
- 主要路径可走通：添加标的 → 查看行情 → 创建规则 → 查看事件 → 记录交易 → 查看持仓 → 写复盘/记日记（含树操作）→ 首页聚合可见。
- 页面不展示没有真实来源的假行情；开发环境模拟数据必须明确标记为模拟。
