# StockCat 页面与交互设计（UI）

- 文档版本：V1.1-Draft
- 目标：定义页面结构、交互与状态；具体视觉细节可在原型阶段调整。
- 配套原型：`docs/prototype.html`（静态 HTML，内含 P0 页面的线框实现、状态样式与弹窗交互；页面数据均为模拟数据，仅用于评审）。
- P0 原则：先可用、清晰、轻量，不追求复杂大屏或 3D 效果。
- 桌面端优先：第一版本地部署、仅在桌面浏览器使用，暂不考虑手机端适配。

## 1. 导航结构

左侧边栏，一级菜单五个分组：

1. **首页 · 总览**——市场概况、重点行情、持仓表现、待处理告警、复盘入口、AI 助手入口卡。
2. **AI 助手**（P2，顶层独立入口）——自由提问，Agent 调只读工具取数并汇总；回答展示数据依据、执行过程与数据限制。
3. **告警**（子菜单）
   - 告警总览：规则状态 + 最近事件 + 通知状态一览。
   - 监控标的：确定告警引擎监控哪些标的。
   - 告警规则：定义触发条件。
   - 告警历史：每次触发的结果与通知状态。
4. **我的股票**（子菜单）
   - 自选列表：关注但不一定持有；页内顶部按自定义分组切换（自选 / 我的组合…）。
   - 我的持仓：由有效交易计算的结果；**持仓变化与收益曲线以页签形式并入此页**（P1.5 起不再单独占导航位）。
   - 交易流水：手工记录每次买卖操作。
5. **复盘**（子菜单）
   - 市场复盘：按交易日记录市场主要情况与不同板块表现；一天一篇。
   - 我的日记：个人长期笔记本，仿飞书文档的树状目录（文件夹/文档），不按日期组织。
6. **其他**
   - 数据源 / 通知配置 / 系统状态（P0）。
   - AI 配置（P2.5，只读状态页，见 §2.12）/ 数据备份（P4 工具化）。

关系约定：**监控标的**决定采集与告警评估范围，与**自选列表**相互独立；一个标的可以只在其中一边。
AI 助手是唯一独立开发的 AI 页面；持仓分析、告警解释、复盘生成等场景后续以按钮嵌入原页面，不各建一个聊天页。

## 2. 页面说明

### 2.1 首页 · 市场与账户总览

目标：打开即回答"市场怎么样、我的持仓怎么样、有没有要我处理的告警"。

栅格布局（三行，2026-10 按用户示意调整；列数自适应，窄窗口自动降为单列，不横向溢出）：
- 第一行 · 市场指标：上证指数 / 深证成指 / 创业板指点位于涨跌幅（内置配置，不属于监控标的）。
- 第二行左 · 持仓概览：浮动盈亏大字 + 持仓市值、持仓数量；点击进我的持仓。
- 第二行右 · 自选与监控：自选涨跌居前（代码+名称+涨跌幅，点击进详情）+ 统计行（自选数 · 监控数/启用数 · 启用规则数）。
- 第三行左 · 最近告警：最近事件（标的、规则、时间），点击进告警历史。
- 第三行右 · 最新复盘：最新一篇市场复盘的日期与标题，无则显示引导文案。
- 第四行 · AI 助手：一句说明 + 三个快捷问题（点击带问题跳转 `/assistant`）+「打开对话页 →」。

交互：任一卡片可点击跳转对应页面；某数据块失败时该卡显示错误态，不影响其他卡。

### 2.1.1 全局布局约定

- 左侧导航固定 200px 且自带滚动；主内容区（`.content`）负责纵向滚动，并拦截页面级横向溢出。
- 页面标题/说明/操作按钮统一用全局 `.page-head`；提示条、按钮高度（30px / 小号 26px）、表格行高、卡片内边距由 `style.css` 统一。
- 所有数据表格外包 `.table-wrap`（`overflow-x: auto`），窄窗口下表格横向滚动、操作按钮始终可见。

### 2.2 AI 助手（P2）

布局：左侧最近对话列表（240px，可删除，存在浏览器 localStorage）+ 右侧对话区（空态建议问题 / 消息流 / 底部输入框）。

一次回答固定四块，缺一不可：
1. **分析结论**：一段自然语言总结。
2. **数据依据**：逐条列出引用到的持仓、行情、告警事实（带时间与状态）。
3. **执行过程**：默认折叠，展开显示调了哪些只读工具、每个是否成功、耗时、结果摘要。
4. **数据限制**：行情截至时间、缺失字段、被排除的内容（如 AI 草稿）。

P3.3 增加**资料引用**（有 `library-search` 命中时才出现，位于数据依据与执行过程之间）：
- 胶囊标签，文字就是后端拼好的「《标题》· 第 N 段」——前端不自己拼出处。
- 点击跳 `/library?doc={id}&chunk={seq}`，资料页打开那篇并滚动高亮那一段，
  然后把参数从地址栏抹掉（资料只在本机，这不是可分享的链接）。
- 回答实际引用几条列几条；一条都没对上（规则模式）时列全部命中。

状态与诚信约定：
- 顶部徽标显示「模型已配置 · 模型名」/「未配置模型 · 规则汇总模式」/「AI 服务未启动」；后两者用琥珀色而非错误色。
- `mode=rule_based` 时回答上方必须显示降级说明（`degraded`），不能让规则汇总被误读为模型分析。
- 请求失败显示错误原因与原问题，提供「重试」；不自动重试（避免重复计费）。
- AI 只读：页面不提供任何写入动作；会话不落库，刷新后仍在但清浏览器数据即消失。

### 2.3 告警总览

- 规则统计：启用中 / 已停用数量。
- 今日事件列表（最近 10 条）：时间、标的、规则、通知状态。
- 通知渠道健康：邮件 / 推送渠道最近发送结果。

### 2.4 监控（原「监控标的」）

表格列：代码、名称、类型、持仓（由交易流水实时推导：当前净持仓 > 0 显示「持仓中」）、最新价、涨跌幅、行情时间、数据状态、监控状态（启用/停用）、操作。
交互：
- [添加监控] 弹窗：市场（P0 仅 A 股）、代码、类型；名称由服务端主数据补全。**可勾选「同时创建告警规则」**（默认开启）：选择类型/阈值/冷却，规则名按 `{标的名称} {条件}{阈值}` 自动拼接，创建失败不影响已添加的监控。
- 停用后不参与采集与告警评估，保留配置。
- 移除需确认（其告警规则保留，可在规则页清理）。

### 2.5 告警规则

规则列表字段：规则名称、标的、规则类型、参数摘要、启用状态、冷却时间、最近触发时间、操作。
P0 类型：`PRICE_ABOVE` / `PRICE_BELOW` / `CHANGE_PERCENT_ABOVE` / `CHANGE_PERCENT_BELOW`。
P1 已实现：MACD/KDJ 金叉死叉、RSI 上穿/下穿、`PREMIUM_ABOVE` / `PREMIUM_BELOW`（溢价率）。
参数约定：`params` 结构由规则类型决定——价格类填价格；涨跌幅/溢价率类用百分数值，跌幅与折价用负数（如"跌 20%"填 `-20`，"折价 1.5%"填 `-1.5`）。条件判断含边界（≥ / ≤）。
评估时机（表单下方必须写明）：行情类与溢价类盘中每 30 秒；指标类收盘后 15:40。
创建/编辑表单（参数表单随规则类型切换）：
- 规则名称（**自动拼接**：`{标的名称} {条件}{阈值}`，如「贵州茅台 价格≥1000」；编辑时可改名）
- 标的（单选，取自监控标的；或切换为"多选"批量创建同类型同参数规则）
- 规则类型 → 对应的参数输入（价格/涨跌幅/溢价率各一个阈值；RSI 多一个周期）
- 冷却时间（非负整数，默认 30 分钟）
- 是否启用
- 服务端校验：溢价类规则只对 ETF/LOF 开放——选中股票时选项置灰并标注"仅 ETF/LOF"，后端创建/改类型时同样拒绝。
  溢价率基准：ETF 用实时 IOPV；LOF 只能用已公布净值，净值超过 3 天未更新时不判定（`maxStaleDays` 可覆盖）。
交互：保存成功后更新列表；停用规则不再产生新事件但保留历史；删除需二次确认，历史事件保留规则类型与参数快照。
多规则：同一标的可同时挂多条不同类型/不同参数的规则（如 a 股票同时监控溢价率、价格、跌幅），各规则独立评估、独立冷却、独立产生事件；规则列表支持按标的筛选，查看某只股票的全部规则。

### 2.6 告警历史

列表字段：触发时间、标的、规则名称、条件快照、触发值、当时涨跌、行情时间、通知状态、操作[AI 解释]。
筛选：时间范围、标的、规则、通知状态；分页，默认触发时间倒序。
详情弹窗：规则快照、触发时行情、通知记录列表；失败通知可重试（仅 FAILED 可重试）。

**AI 解释（P2 场景二）**：点击行内 [AI 解释] 打开右侧抽屉，不离开列表。内容固定四段 + 数据限制：

1. **为什么触发** —— 条件文案 + 触发时的实际观测值（如「DIF 0.0123 上穿 DEA 0.0101」）；
2. **这意味着什么** —— 该指标的现象与局限，不含买卖建议；
3. **当前状态** —— 当前价格/涨跌与最新指标，和触发时有差异时点明（如「已发生反向穿越」）；
4. **数据依据** —— 可逐条引用的观测值；
5. **数据限制** —— 行情时间、指标所属交易日、快照缺失项。

诚实原则（UI 必须如实呈现，不得美化）：
- 事件快照没有保存某个指标时，抽屉顶部显示黄色提示，正文写「快照没有保存 X 数值，无法给出当时的具体值」，
  **不得回算**；此时不启用模型改写，避免模型补一个"合理"数字。
- 当日 K 线尚未更新时，明确写「与触发时是同一根 K 线，不代表触发之后的变化」。
- `mode=rule_based` 时页脚显示「模板生成 · 未使用模型」。
- 页脚 [在 AI 助手中继续追问] 跳转 `/assistant?q=...`，自动带入这条告警的上下文。
- AI 服务未启动时抽屉内显示可操作提示（启动 `backend-python`），列表本身照常可用。

### 2.7 自选列表

表格列：代码、名称、市场/类型、最新价、涨跌幅、**溢价（P1.4，仅基金）**、行情时间、采集时间、数据状态、操作。
交互：[添加自选] 弹窗；移除确认；点击代码/名称或[K 线]按钮进入标的详情（`/stocks/{id}`）。
溢价列：显示带符号的百分数 + 基准小标签（`IOPV` / `净值(T-x)`），悬停提示价格/IOPV/净值/基准时点；
溢价为正红色、为负绿色（与全站红涨绿跌一致）；股票显示 —；基金无数据显示 — 并说明原因，不显示 0.00%。
说明：自选与监控标的独立管理，互不影响。
**自定义分组（V7）**：表格上方为分组页签「自选 / 我的组合…」（带数量角标）+ [＋新建分组]；
每个标的只属于一个分组（NULL = 默认自选），行内下拉可直接移动分组；添加弹窗可选分组；
新建分组时自动带上分组名打开添加弹窗，随第一个成员加入而创建、移空后自然消失（不需要单独管理分组）。

### 2.7.1 标的详情（P1.7）

路由 `/stocks/{id}`，从自选列表点入。一屏内回答三个问题：这只标的最新多少、最近走势如何、指标处于什么位置。

- 头部：标的名 + 代码 + 类型；右侧为周期/复权切换与[同步历史]。
  P1 只有**日 K + 前复权**可选，其余选项置灰并给出原因（不做一个点了没反应的按钮）。
- 行情条：最新价、涨跌幅、昨收、行情时间、数据状态、最新 K 线日期、库中根数、最后同步时间。
  快照缺失一律显示"—"，不按 0。
- 图表（ECharts 多 pane，共用 x 轴与缩放）：
  1. K 线（红涨绿跌）
  2. 成交量（手；按当根涨跌着色）
  3. MACD(12,26,9)：DIF/DEA 折线 + 柱（柱=2×(DIF−DEA)）
  4. RSI(6,12,24)：固定 0~100 轴，20/50/80 虚线
  5. KDJ(9,3,3)：K/D/J，J 不裁剪
  默认展示最近 120 根，可切 60/120/250/500；底部滑块 + 滚轮缩放；十字光标跨 pane 联动。
- 状态：
  - 未同步（`count = 0`）：不画图，说明"是没同步，不是没行情" + [同步最近 120 根]。
  - 数据不足：副图标题追加"数据不足（需 N 根）"，顶部提示缺多少根，不补 0。
  - 指标接口失败：K 线与成交量照常显示，副图标题写"指标加载失败"。
  - 同步失败：`DATA_SOURCE_UNAVAILABLE` 明确提示"Python 数据服务未启动"，不显示成通用错误。
  - 最后同步超过 24 小时：提示可能不是最新，不擅自断言"过期"。
- 脚注：写清指标口径（对齐通达信）与"不构成投资建议"。
- **基金参考数据区块（P1.4，仅 ETF/LOF 显示）**：
  - 四个指标位：溢价率（带基准与时点）、参考净值 IOPV（带时间；LOF 显示"只有 ETF 有实时 IOPV"）、
    单位净值（带净值日期与滞后天数）、价格（带行情日期）。
  - 最近 10 个交易日小表：日期、价格、单位净值、净值日期、IOPV、溢价、基准。
  - [刷新参考数据]：同时刷腾讯 IOPV/价格与净值，结果如实显示（部分成功要说明哪部分失败）。
  - 文案硬规则：ETF 溢价注明"基准 IOPV（实时）"；LOF 溢价注明"基准净值(T-x)"——**不允许把滞后净值说成实时**。
  - 脚注写明溢价公式与"两者都没有时留空，不用别的数顶替"。
  - 股票详情页整个区块不出现（不显示一个"不适用"的空壳）。


### 2.8 我的持仓（P1.5 扩展为三页签）

页签：**当前持仓 / 收益曲线 / 持仓变化**，右上角固定「重建快照」「刷新」，收益曲线与持仓变化页签额外有区间选择（近 1 月 / 3 月 / 6 月 / 1 年）。

**当前持仓**（由流水实时重放，不看快照）

表格列：标的、持有数量、摊薄成本、最新价、市值、浮动盈亏、浮动收益率、已实现盈亏、价格状态。
- 市值/浮动盈亏基于最新有效快照；快照缺失或过期时显示"—"，不按 0 计算。
- 空状态：尚无持仓，引导去记录交易流水。

**收益曲线**（由 `position_snapshot` 按日聚合）

- 顶部四张卡：期末总市值（含区间变化）、累计收益（浮盈 + 已实现）、简单收益率（净投入）、期末持仓成本（含快照日）。
- 图表：左轴金额（总市值实线 + 持仓成本虚线）、右轴累计收益（0 处虚线基准）；十字光标联动显示三个值。
- 缺价提示：区间内有 `complete=false` 的天数时，顶部黄色横幅说明"市值只统计了能取到价的部分，请先同步历史（不复权）再重建"。
- 脚注必须原样展示后端 `note`：简单收益、不复权、未调整分红送股、未做资金加权。
- 空状态：说明快照来源（流水 + 不复权收盘价）、收盘后 15:45 自动生成，并提供「立即重建快照」按钮。

**持仓变化**

表格列：标的、期初（数量 + 日期）、期末（数量 + 日期）、数量变化、成本变化、市值变化、浮盈变化、区间已实现、成交笔数、状态。
- 状态标签：`区间内清仓` / `新开仓`（期初无快照）/ `持有中`。
- 期初取"区间起点之前的最后一条快照"；区间内开仓又清仓时数量变化为 0，用「区间内清仓」+ 区间已实现表达。
- 空状态：换更长的区间，或先重建快照。

**全局说明**：持仓由交易流水计算，非券商同步数据；收益曲线收盘价用不复权口径。

### 2.9 交易流水

表格列：成交时间、标的、方向（买入/卖出）、成交价、数量、费用、金额、备注、操作[删除]。
筛选：标的、方向、时间范围。
交互：
- [记录交易] 弹窗：标的、方向、成交价、数量、费用、成交时间、备注。
- 卖出数量超过持有量时，后端拒绝（409）并在表单显示"当前可卖 N 股"。
- 删除流水需确认；删除后持仓自动重算。

### 2.10 市场复盘

一天一篇（已存在时显示"查看/编辑今日复盘"）。
列表列：日期、标题、更新时间、操作。
编辑器分区：**市场主要情况** / **板块表现** / 完整正文（Markdown）/ 关联告警事件多选。
检索：日期范围、关键词。
交互：保存成功反馈；删除二次确认；AI 草稿（P2）带"AI 草稿"标识，用户确认后才转为正式复盘。

**AI 草稿（P2.5 已实现）**

- 页头「✨ AI 生成草稿」：按当前选中复盘的日期生成（没选中则今天）。当天已有正式复盘时按钮置灰，

**AI 辅助（P2 场景四，2026-10-27 实现）**——两个入口都是弹窗，都只出建议，**不自动改正文**：

  - 命中 0 篇时直接说"没有找到包含「X」的日记，因此不做任何总结"，且**不调模型**——
    没有素材的总结一定是编的。
- 两个面板都有 `mode` 徽标（`模型整理`/`规则提取`、`模型归纳`/`仅检索罗列`）与耗时，降级原因用 banner 展开写。

### 2.13 数据源与系统状态（P0 承诺，2026-10-27 实现）

两个页面都只读，数据都来自同一个 `GET /system/status`——不各建一套探活，避免两页显示不一致。

**数据源**（`/settings/data-source`）

- 顶部一行说明"共 N 个数据源、启用 M 个"；有源上次失败时给红色提示条并列出是哪几个。
- 每个源一张卡：名称 + 提供方 + 「启用/停用」与「正常/失败/未运行」两个徽标；
  下面 `dl` 列出地址（等宽）、频率（人话 + 悬停看 cron）、上次运行、上次成功、结果摘要与错误。
- 没有独立统计的源（如 IOPV 随实时行情执行）**显示「无独立统计」**，不编一个"正常"。
- 卡底一行虚线分隔的口径说明：该源取的是什么、缺了会怎样。
- 页尾固定四条小字：采集时点快照不是收盘价 / 净值是日终值 / 不回显凭据 / 任务统计重启清零。

**系统状态**（`/settings/status`）

- 页头徽标给整体判断（运行中 / 有任务失败 / 采集降级 / 数据库异常），右侧「重新检查」。
- 四张卡：Java 应用、PostgreSQL、实时行情采集（含连续失败次数与错误码）、AI 服务（Python 状态 + 模型名或"规则模式"）。
- 数据库 `DOWN` 时顶部出红色横幅，直接说"先确认 PostgreSQL 与连接串"；`NOT_CONFIGURED` 单独一色，不当故障。
- 「收盘后任务」表：任务 / 状态 / 上次运行 / 上次成功 / 结果。从未运行的显示"本进程启动后还未运行过"，
  而不是空白——空白最容易被当成"没问题"。
- 页尾小字说明：统计是内存态、重启清零、不含密码与 token。

通知配置页（P0.6）：Server酱渠道状态（只显示"已配置 / 未配置"，不回显 SendKey）、测试发送、
最近通知列表与失败重试。**邮件渠道未实现**——PRD §2.1 目标 6 要的是"邮件 + 一种已验证的推送渠道"，
目前只有推送这一半，缺口登记在 `BACKLOG.md §2.1`。

### 2.14 资料库（P3.1，2026-10-27 实现）

侧边栏独立一组「资料」。左列表右详情，同一页完成导入、查看、删除（不做二级路由：
资料的操作都是"选一篇看一眼"，跳页会打断对比）。

- 左栏：搜索框（匹配标题与正文，输入即搜，300ms 防抖）+「粘贴导入」「上传文件」；
  列表项显示标题、来源徽标（粘贴/文件）、发布方、日期、`N 字 · M 段`。
- 右栏：标题与元信息（来源、文件原名、发布方、发布日期、导入日期、字数与片段数）、
  正文（`pre-wrap` 保留换行）、可折叠的片段列表（第 N 段 · 标题 · 字符区间 · 前 120 字）。
  片段列表不是给用户读的，是让"检索单位是段不是篇"这件事看得见。
- 底部一行固定说明 + 删除按钮：`资料导入后不可编辑：要换内容就重新导入，重复的正文会被拦住。`
- 粘贴弹窗：标题 / 来源 / 日期 / 正文。弹窗内写明只收粘贴与 .md/.txt，
  并解释为什么 PDF 与 HTML 不行（PDF 没有段落、HTML 带导航页脚），给替代做法而不是让人猜。
- 重复导入：后端 `409` 的 message 直接显示在弹窗里（含已存在资料的 id），不算"导入失败"。
- 删除：原生 `confirm`，写明会删掉几个片段、不可恢复。
- 空状态：`还没有资料。粘贴一篇，或上传 .md / .txt 文件。`

**片段级检索（P3.2，同日加）**——搜索框从"筛列表"改成"查片段"，但**不换页**：

- 有关键词时左栏变成命中片段列表，每条显示：资料标题、`第 N 段 · 小节标题`、
  `仅标题命中` 徽标（如果有）、日期、以及命中位置前后各约 60 字的 snippet（关键词高亮）。
  清空搜索框回到文档列表与分页——检索与浏览是同一件事的两个入口，分成两页会让"我刚看的那篇"丢掉。
- 点一条命中：右侧打开那篇资料，**滚动到那一段并整段高亮**。正文按片段渲染（重叠部分由游标裁掉），
  所以定位是精确的，不是按字数比例估算。
- 片段列表上方写`按「渠道库存」查找`，把拆词结果摆出来——用户才知道系统把查询拆成了
  渠道 / 道库 / 库存三个词，也才理解为什么命中段落的高亮是零散的几个两字词。
- **结果条数可以少于 5 条，不补占位、不提示"结果较少"**。P3.4 之后有两条门槛
  （命中 ≥2 个 bigram、多词查询每个词都要命中），长查询常常只返回 1–2 条。
  凑满 5 条就要拿噪声充数，而"只有 2 条"本身就是质量信号。
- 无结果：`没有找到与「X」相关的资料。` 下一行固定说明`只匹配标题与正文里的原文，不猜近义词。`
  不出现"相关推荐"。
- 走检索时**不再**做文档级筛选（原来的 `keyword` 列表参数在页面上不再使用，接口保留）。

## 3. 全局交互状态

每个数据页面都要定义：
- 初次加载：骨架屏或加载提示。
- 空状态：解释为什么为空，并提供下一步操作。
- 请求失败：错误提示 + 重试入口。
- 部分数据缺失：明确标记，不用 0 代替未知值。
- 数据过期：展示最后更新时间。
- 保存中：禁用重复提交并显示进度。
- 操作成功：明确反馈。
- 删除/不可逆操作：确认后执行。
- 服务未启动：提示检查服务状态，不暴露内部异常详情。

## 4. 视觉风格建议

- 简洁的金融工具风格，信息密度适中。
- 使用中性色为主；涨跌色遵循 A 股惯例**红涨绿跌**，全站一致。
- 状态不能只依赖颜色，同时配文字或图标。
- 数字采用等宽数字或对齐格式；价格小数位按品种精度（A股 2 位），涨跌幅固定一位小数，百分比统一"百分数值"。
- 不使用夸张的"买入/卖出"按钮，不把指标展示包装成确定性投资结论。
- 桌面端优先（设计基准宽度 ≥1280px），暂不考虑手机端适配。

### 2.15 备份（2026-10-27，P4 前置小件提前实现）

侧边栏「其他」组，替换掉原来的占位页（全站最后一个占位页）。

- **导出卡**：「立即备份」按钮 + 两条元信息——保存位置（后端返回的**绝对路径**，
  用户得知道文件落在哪）与执行命令（当前实际会跑的 `pg_dump` 命令，方便排查）。
  docker 模式下加一行固定说明：宿主机没有 pg_dump，借用容器里的那个，
  **Docker Desktop 与容器必须在运行**；容器没起会直接报错，不会生成空文件。
- **备份历史**：文件名 / 大小 / 备份时间（导出完成时刻）/ 下载 / 删除。
  按时间倒序。空态：`还没有备份 —— 点「立即备份」生成第一份`。
- 删除用原生 `confirm`，写明「删除只影响这个备份文件，库里的数据不受影响」。
- **恢复区是页面上最重要的部分，标题就是「恢复（页面不提供）」**：
  红边卡片，先讲清 `--clean --if-exists` 会覆盖整个库、为什么不做按钮
  （点错一次，交易流水就退回备份那天），再给四步命令行指引：
  ① 先再导出一份当前状态兜底 → ② 关后端 → ③ 执行后端拼好的 `pg_restore` 命令
  （占位符替换成实际路径）→ ④ 重启后端核对首页。
  下载按钮放在每行而不是恢复区，避免"想恢复"和"能下载"被混为一谈。
- 导出按钮请求超时放宽到 5 分钟（与后端 pg_dump 上限一致）；
  默认 10 秒会让前端先放弃、后端还在写文件。
