## 2. 日 K：东财 push2his

### 2.1 请求

```
GET https://push2his.eastmoney.com/api/qt/stock/kline/get
  ?secid={market}.{code}
  &fields1=f1,f2,f3,f4,f5,f6
  &fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61
  &klt=101&fqt=1&beg=20260701&end=20500101
```

| 参数 | 说明 | 实测结论 |
|---|---|---|
| `secid` | `1.` = 上交所，`0.` = 深交所 | `1.600519` 沪市 ✅、`0.000001` 深市 ✅、`1.000001` 上证指数 ✅、`1.510300` ETF ✅、`0.161725` LOF ✅ |
| `klt` | K 线周期 | `101` 日 K ✅（`102` 周、`103` 月 未验证） |
| `fqt` | 复权 | `0` 不复权 ✅、`1` 前复权 ✅、`2` 后复权 ✅（三者实测均返回数据） |
| `beg` / `end` | 起止日期 `YYYYMMDD` | `beg=20261010` 生效 ✅；`beg=0` 返回全部历史（茅台 6028 条一次返回） |
| `lmt` | 条数限制 | ⚠️ 实测**不生效**（`lmt=5` 仍返回全量）。**必须用 `beg` 控制窗口，不要依赖 lmt** |

### 2.2 字段映射（`fields2` 顺序 → 返回 CSV 列顺序）

| 列 | 字段 | 含义 | 单位/精度 |
|---|---|---|---|
| 1 | `f51` | 日期 | `YYYY-MM-DD` |
| 2 | `f52` | 开盘价 | 元 |
| 3 | `f53` | **收盘价** | 元（注意：第 3 列是收盘，不是最高价） |
| 4 | `f54` | 最高价 | 元 |
| 5 | `f55` | 最低价 | 元 |
| 6 | `f56` | 成交量 | **手**（1 手 = 100 股/份） |
| 7 | `f57` | 成交额 | 元 |
| 8 | `f58` | 振幅 | 百分数值 |
| 9 | `f59` | 涨跌幅 | 百分数值（2.5 = 2.5%） |
| 10 | `f60` | 涨跌额 | 元 |
| 11 | `f61` | 换手率 | 百分数值 |

交叉验证：茅台 `2026-10-26` 的 K 线收盘 1349.98、最高 1350.00、最低 1324.79、开盘 1325.40，与东财 push2 实时快照 `f43/f44/f45/f46` 完全一致 ✅

### 2.3 实测到的坑（必须在实现里处理）

1. **前复权长期历史会出现负价**
   茅台 `fqt=1&beg=0` 的最早一根（2001-08-27）开 `-312.68`、收 `-312.47`。原因是累计分红金额超过当年股价，前复权按当前价倒推必然为负。
   对照 `fqt=2`（后复权）同日为开 `34.51`、收 `35.55`，正常。
   → **结论：前复权只用于有限窗口（默认最近 250 根，硬上限 500），不做全历史前复权。** 落库前校验 `close > 0`，出现非正值直接拒绝入库并记日志（不静默接受脏数据）。

2. **盘中会返回未收盘的当日 K 线**
   16:20 拉取时已包含 `2026-10-26` 一整根。盘中拉取同样会带上当日未走完的 bar。
   → **结论：同步任务必须在收盘后运行（默认 15:30），并在写入前校验"当日 bar 的日期 < 今天 或 已过收盘时间"**。P1 不加 `is_final` 列，靠调度时间 + 校验保证；若将来做盘中历史刷新，再补该字段。

3. **非法代码返回 `rc=100`，`data=null`**
   `1.999999` → `{"rc":100,"data":null}`。这是明确的错误信号，直接映射 `DATA_SOURCE_UNAVAILABLE`。

4. **合法代码也可能 `rc=0` 但 `klines=[]`**
   北交所 `0.835185` → `rc=0`，`name="贝特瑞(已切换)"`，`klines=[]`。
   → **结论：不能用 `rc=0` 判定成功。成功条件必须是 `rc==0 && data != null && klines 非空`。** 空数组一律按"无数据/不支持"报错，绝不能当成"该标的没有历史"写入库里。

5. **停牌日不缺行、非交易日无行**
   K 线天然只有交易日。日期间会有跳跃（周末、节假日、停牌）——指标按 bar 顺序计算即可，但**指标窗口不能按自然日推算**（如"30 天前的 MACD"），必须按 bar 数。

### 2.4 限频实测

连续 8 只（无 sleep，约 100ms/次）全部 `rc=0` 成功，未触发限频。北交所/非法代码请求约 90~125ms。

→ 结论：单进程串行 + 每次间隔 200ms 足够安全；但 P0 曾遇到 IP 限频（实时 push2），**历史同步仍限制单次批量上限（默认 200 只）并支持断点续跑**，失败标的次日补，不做无限重试。

## 3. ETF / LOF 参考数据

### 3.1 实时快照：腾讯 `qt.gtimg.cn`（含 IOPV）

```
GET https://qt.gtimg.cn/q=sh510300,sz159915,sh512880
Header: Referer: https://gu.qq.com/
```

- 编码 **GBK**，需显式解码；批量一次多只 ✅（返回多行 `v_sh510300="..."`）
- 每行 `~` 分隔共 88 个字段，相关位置：

| 索引 | 含义 | 实测证据 |
|---|---|---|
| 3 | 最新价 | 510300 = 4.179 |
| 4 | 昨收 | 4.178 |
| 30 | 行情时间 | `20261026161432` |
| **77** | 溢价率（百分数值） | 见下方公式验证 |
| **78** | **IOPV / 参考净值** | 仅 ETF 有；股票、LOF 该位为空 |
| 81 | 单位净值 | 510300 = 4.1811（= 天天基金 2026-10-23 净值） |
| 61 | 类型 | `ETF` / `LOF` / `GP-A` |
| 82 | 币种 | `CNY` |

**公式验证（7 只全部吻合，误差 <0.01）**

| 代码 | 名称 | 价格 | idx77（腾讯给的溢价率） | idx78 IOPV | idx81 净值 | 自算 `(price−IOPV)/IOPV` |
|---|---|---|---|---|---|---|
| sh510300 | 沪深300ETF | 4.179 | 0.02 | 4.1782 | 4.1811 | 0.02 ✅ |
| sh510500 | 中证500ETF | 6.75 | 0.01 | 6.7495 | 6.8526 | 0.01 ✅ |
| sh512880 | 证券ETF | 1.021 | −0.18 | 1.0228 | 1.0138 | −0.18 ✅ |
| sh588000 | 科创50ETF | 1.381 | −0.64 | 1.3899 | 1.4215 | −0.64 ✅ |
| sz159915 | 创业板ETF | 2.651 | −0.18 | 2.6559 | 2.7018 | −0.18 ✅ |
| sz161725 | 白酒LOF | 0.544 | 1.78 | **空** | 0.5345 | 1.78（基准是**净值**） |
| sh501050 | 50AH LOF | 1.592 | −1.06 | **空** | 1.6090 | −1.06（基准是**净值**） |

**这里是最重要的一个结论：**

- **ETF**：idx77 的基准是实时 IOPV（可靠，可用于盘中溢价监控）。
- **LOF**：没有 IOPV，idx77 的基准是**上一交易日收盘净值**（161725 的 0.5345 已核实为 2026-10-23 的净值，今天 10-26 收盘后尚未更新）。
  → **LOF 的"溢价率"在盘中是不准的**（净值是 T-1 的）。因此：**不使用腾讯给的 idx77**，只取 `idx78` 与 `idx81`，在 Java 里自己算并带上基准标识：

```json
{ "premiumRate": 1.78, "premiumBasis": "NAV", "premiumAsOf": "2026-10-23", "staleDays": 3 }
{ "premiumRate": -0.18, "premiumBasis": "IOPV", "premiumAsOf": "2026-10-26T14:59:00+08:00" }
```

- 溢价率**只对 ETF 且 IOPV 非空时用 IOPV**；否则用 NAV 但必须标 `premiumBasis=NAV` 并在前端注明"基准为 T-x 净值"；两者都没有 → `null`，不猜。

### 3.2 日终净值：天天基金 `f10/lsjz`（权威历史）

```
GET https://api.fund.eastmoney.com/f10/lsjz?fundCode=510300&pageIndex=1&pageSize=20
Header: Referer: https://fundf10.eastmoney.com/
```

返回关键字段：`FSRQ`（净值日期）、`DWJZ`（单位净值）、`LJJZ`（累计净值）、`JZZZL`（日增长率）。

- ETF/LOF 都支持 ✅（`510300`、`161725` 均已验证）
- 需要 `Referer`，缺失是否被拒**未验证**（实现时固定带上）
- 净值是**收盘后公布**，因此 T 日的净值通常 T 日晚上才有；盘中拿到的最新净值必然是 T-1 或更早 → 这正是上表 `premiumAsOf` / `staleDays` 的意义

> `fundgz.1234567.com.cn/js/{code}.js`（实时估值）对 ETF 返回 404，**不使用**。

## 4. 对 P1 计划的修订（相对 docs/PLAN_P1.md）

| 项 | 原计划 | 实测后修订 |
|---|---|---|
| D1 抓取归属 | 历史/基金数据全部走 Python | **日 K + 日终净值** 走 Python；**实时 IOPV + 最新净值** 走 Java 新增 `TencentQuoteClient`（与东财实时快照并列），保证溢价告警不依赖 Python |
| D4 复权 | 前复权为基准 | 前复权窗口硬上限 500 根；`close<=0` 拒绝入库 |
| D5 溢价率 | `(price−IOPV)/IOPV` | 增加 `premiumBasis`（IOPV/NAV）与 `premiumAsOf`、`staleDays`；LOF 只能用 NAV 基准并标注 |
| P1.2 落库 | `kline_daily` | 表结构不变；增加"当日未收盘 bar 拒写"与"非正值拒写"两条校验 |
| P1.4 基金数据 | Python 抓 + Java 落库 | 净值走 Python→Java；IOPV 走 Java 实时链路；`fund_reference` 增列 `premium_basis` 与 `nav_date` |

`kline_daily` 建议补充的列（原计划无）：

```
kline_daily(
  ...,
  adjust VARCHAR(8) NOT NULL,       -- raw / qfq / hfq
  source_code VARCHAR(32) NOT NULL, -- eastmoney-push2his
  change_percent NUMERIC(12,6),     -- f59
  turnover_rate  NUMERIC(12,6),     -- f61
  fetched_at TIMESTAMPTZ NOT NULL DEFAULT now()
)
```

### 7.2 腾讯 `qt.gtimg.cn`

| 项 | 结论 |
|---|---|
| 编码 | GBK，响应头 charset 不可靠，必须拿字节自己解码（乱码名称是典型症状） |
| 字段位（88 个 `~` 分隔） | `3` 最新价、`4` 昨收、`30` 行情时间 `yyyyMMddHHmmss`、`61` 类型（ETF/LOF/GP-A）、`78` IOPV（**仅 ETF**，LOF/股票为空串）、`81` 最新公布净值、`82` 币种 |
| idx81 在晚间的表现 | 收盘后到晚间会更新为 T 日净值（22:40 实测 510300=4.1797 = lsjz 同日值）。但它**不带日期**，白天无法区分是 T 还是 T-1 —— 所以**净值只从 lsjz 取（带 FSRQ）**，idx81 仅作参考不参与溢价计算 |
| 溢价率 idx77 | 不使用：ETF 基准是 IOPV 没问题，但 LOF 的基准是 T-1 净值却无任何标注。溢价一律在 Java 里自算并标 `premiumBasis` |
| 代码前缀 | 6/5/9 → `sh`，0/1/2/3 → `sz`（与东财 secid 规则一致）；北交所 8xx/4xx 不支持 |

### 7.3 数据形态约定（落库与展示）

- 同一交易日的 IOPV/价格（盘中）与净值（晚间）落在 `fund_reference` 的**同一行**，两条 UPSERT 用 COALESCE 互不覆盖。
- 净值行必须能对上日期：**没有 `nav_date` 的净值不展示、不算溢价**（无法判断是哪天的数）。
- 溢价率三规则见 `docs/API.md` §3.5；验收核对：510300 IOPV 基准 0.0191% ✅、161725 NAV 基准 −0.348% ✅（均为 2026-10-26 实测，与手算一致）。
