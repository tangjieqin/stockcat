# StockCat 开发计划与验收清单

- 文档版本：V1.0-Draft
- 开发方式：小步交付；每个阶段结束都能运行、演示和测试。
- 部署定位：第一版目标是**本地单机端到端闭环**——先打通本地环境和完整链路，再逐步增加历史行情、指标和 AI。云服务器、HTTPS/公网部署、多用户权限等工作暂不安排（P4 再评估）。
- 原则：AI 先阅读文档和仓库，再按一个小任务修改；每次检查 diff、运行测试并提交版本控制。

## 0. 开工前准备

### 任务

- 建立仓库目录：`frontend/`、`backend-java/`、`backend-python/`、`docs/`。
- 将六份设计文档纳入版本控制。
- 建立 `.gitignore`、`.env.example`、README。
- Java 数据访问方案已定：**MyBatis**；全项目统一使用，不在不同模块混用其他方案。
- 迁移工具已定：**Flyway**。
- 锁定已验证的 Java、Node、Python、PostgreSQL 版本。
- 验证行情源和通知渠道的基本可访问性与使用条件。

### 验收

- 本地可启动空白 Vue、Spring Boot、FastAPI 和 PostgreSQL。
- 健康检查可访问。
- Git 仓库不含真实 token、密码或 `.env`。

## P0：行情、告警、持仓与记录闭环（本地可用版本）

### P0.1 后端基础骨架

交付：

- Spring Boot 应用、配置分层、统一错误响应、参数校验。
- PostgreSQL 连接、Flyway 迁移和首批 schema。
- `/api/v1/system/health`、`/api/v1/system/status`。
- Python FastAPI `/health`。

验收：

- 应用可启动；数据库不可用时健康状态准确。
- API 错误结构统一；基础测试通过。

### P0.2 标的主数据与监控标的

交付：

- `instrument`、`monitor_target`；监控标的 CRUD/启停。
- 监控标的列表页（含最新行情状态）。

验收：

- 添加重复监控标的返回冲突；停用后不参与采集与告警评估。

### P0.3 自选与实时行情

交付：

- `watchlist_item`；自选查询/添加/删除 API 与页面。
- `RealtimeQuoteService` / `RealtimeSnapshotCollector`：数据源客户端、字段映射、超时和限流处理。
- 行情快照表和最新行情 API；行情总览表格。

验收：

- 对真实可用标的能展示来源、行情时间和采集时间。
- 数据源失败时显示异常/过期状态，不以 0 替代。
- 单元测试覆盖字段映射、缺失字段和异常场景。
- 标的主数据无法验证时不生成虚假名称。

备注：若行情源尚未验证，先实现明确标记为模拟的测试适配器；不得将模拟结果冒充真实行情。

### P0.4 交易日历与采集调度

交付：

- A 股 `trading_calendar` 数据模型；交易时段判断、采集间隔配置和定时任务。
- 首页指数标的内置配置与采集（上证指数/深证成指/创业板指）。
- 最近成功时间、失败统计和日志。

验收：

- 非交易日/非交易时段按配置执行；任务不会在单进程中重入。
- 节假日数据来源、更新方式和失效处理写入 README。

### P0.5 告警规则与事件

交付：

- 规则 CRUD/启停；`AlertEvaluationJob`。
- 事件生成、去重键和冷却机制；事件查询 API 与前端列表。

验收：

- 价格/涨跌幅四种条件覆盖单元测试。
- 过期/无效行情不触发正常事件；连续满足条件时冷却逻辑生效。
- 删除规则后历史事件仍可解释。

### P0.6 通知链路

交付：

- 邮件发送器；一个经验证的推送渠道（Server酱或 PushPlus，选一个）。
- `notification_record`、失败原因、手动重试；通知配置页。

验收：

- 测试环境能发送真实测试通知，或明确标注因凭据/外部服务未配置而未验收。
- 事件已生成但通知失败时，事件仍保留；已发送成功的通知不能被误重复重试。

### P0.7 交易流水与持仓

交付：

- `trade_record` CRUD；持仓聚合计算服务（摊薄成本、浮动/已实现盈亏）。
- 交易流水页、我的持仓页；超卖校验（`409 CONFLICT`）。
- 持仓计算单元测试：多笔买入、部分卖出、清仓后再买入、超卖拒绝、费用计入成本。

验收：

- 录入一买一卖后，数量/摊薄成本/已实现盈亏与手工计算一致。
- 卖出超过持有量被拒绝并提示；删除流水触发受影响持仓重算。

### P0.8 复盘与我的日记

交付：

- `market_recap`：市场复盘创建/编辑/删除/查询 API（一天一篇，含市场主要情况与板块表现分区）。
- `diary_node`：树状笔记本 API（整树查询、节点增删改、移动含成环/深度校验、关键词搜索）。
- 市场复盘页与"我的日记"页（左树右文，仿飞书文档）。

验收：

- 同一交易日重复创建复盘返回冲突；复盘与日记分开存储、分别检索。
- 树操作完整：新建文件夹/文档、重命名、移动、删除；移动到自己子孙下被拒绝（400）。
- 删除文件夹需强确认并提示将删除的文档数；关联的告警事件可跳转查看。
- P2 的 AI 草稿不得覆盖手工内容。

### P0.9 首页总览与集成验收

交付：

- `GET /dashboard` 聚合接口；首页（市场概况、重点行情、持仓表现、待处理告警、复盘入口）。
- 告警总览页；全部 P0 页面的加载、空、错误、过期、部分失败状态。
- README 的本地启动与排障步骤。

验收：

- 完成“添加标的 → 显示行情 → 设置规则 → 触发事件 → 查看通知 → 记录交易 → 查看持仓 → 写日记”的端到端演示。
- Java/Python/前端自动化测试通过。
- 未实现功能明确标记，不出现假数据或虚构成功状态。

## P1：历史行情、技术指标与基金参考数据

任务：

1. 验证并实现 Python 历史 K 线适配器。
2. Java 校验和持久化 K 线。
3. Java 计算 MACD、RSI、KDJ（口径对齐通达信；实测 ta4j 口径不一致，改为自研）。
4. 验证 ETF/LOF 的价格、IOPV、NAV 数据来源和字段定义。
5. 展示指标及溢价，并标注数据时点和质量。

验收：

- 数据源和周期已验证，缺失数据有明确处理策略。
- 指标仅在 Java 计算；不在 Python 重复实现。
- 指标结果可用已知测试数据进行核对。
- 溢价率计算和分母定义有文档与测试。

## P2：AI 每日复盘 Agent

任务：

1. 在 Python 集成 LangChain。
2. 定义受控 Java 只读工具：自选行情、持仓与盈亏、告警事件、日记和日期范围查询。
3. 前端 AI 复盘页面调用 Agent，生成**复盘草稿**。
4. 用户在草稿确认页编辑并确认后，保存为 `MANUAL` 日记；记录生成时间、数据范围和限制说明。
5. 对模型失败、工具失败和部分数据缺失设计降级。

验收：

- Agent 只能调用白名单工具。
- Agent 不直接访问业务数据库，不更改规则、不修改交易流水、不覆盖手工日记、不发送通知。
- 未经用户确认的草稿不进入正式日记列表。
- 返回结果标注数据时间；工具失败时不编造行情。
- Python/模型不可用不影响 Java 告警。

## P3：资料检索与 RAG

任务：

- 设计文档导入、去重、来源、时间、权限与删除策略。
- 确认 PostgreSQL pgvector 版本和部署兼容性。
- 构建检索评估集并检查引用可追溯性。

验收：

- 回答能给出资料来源和时间。
- 删除资料时同步处理对应切片和向量。
- 无相关资料时明确说明，不补造出处。

## P4：扩展与部署（暂缓，第一版不安排）

任务：

- 评估港股、美股、更多基金和数据源。
- 评估云部署、备份恢复、HTTPS、身份验证、监控和费用。
- 根据真实需求再考虑多用户或消息队列。

验收：

- 新市场有独立交易日历、时区、货币和交易时段测试。
- 备份可以实际恢复。
- 公网部署前完成安全检查。

## AI 编程协作约定

每个任务给 AI：

1. 本任务目标和明确不做的内容。
2. 相关设计文档。
3. 当前目录结构和相关代码。
4. 输入/输出契约及验收标准。
5. 要求先说明计划，再修改少量文件；禁止顺带重构无关模块。
6. 要求运行相关测试并汇报实际结果；没有运行的测试不得声称通过。
7. 要求列出新增/修改文件、关键设计选择、未解决风险和手工验证步骤。

## 建议的任务粒度

一次只做一个可验证闭环，例如：

- 先做健康检查，而不是“把后端都写完”。
- 先做自选查询/添加/删除，再做行情接入。
- 先用测试夹具验证规则，再接入真实通知。
- 每完成一个任务，人工检查 diff、运行测试并提交 Git。
